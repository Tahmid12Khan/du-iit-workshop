A good prompt has six parts

  1. A short order has one part. The cook must guess.
  2. Add a role. The role tells the model who to be.
  3. Add context. Context tells the model about the situation.
  4. Add examples. Examples show the model the answer you want.
  5. Add constraints. Constraints list what the model must not do.
  6. Add a format. The format tells the model how to write the answer.
[STEP 1] model ভুল বলতে পারে, এটা দেখলাম। এবার প্রশ্ন, ভালো prompt লিখলে কি ভুল কমে? ধরো তুমি মেসের বাবুর্চিকে বললে, "ভাত আর ডাল রাঁধো।" বাবুর্চি কীভাবে রাঁধবে? ঝাল দেবে কি না, কীসে দেবে, কতটা বানাবে? সে অনুমান করবে। model-ও ঠিক এমন। সে তোমার মাথার ভেতরটা দেখতে পায় না, শুধু তোমার লেখাটুকু পায়। শুধু task দিলে সে অনুমান করে। এই task-টাই প্রথম অংশ। [ASK] তোমরা কেউ কি এমন ছোট prompt লিখে ভুল উত্তর পেয়েছ? [PAUSE 3s] [STEP 2] এবার দ্বিতীয় অংশ, role। বাবুর্চিকে বলো, "তুমি আমাদের মেসের বাবুর্চি।" model-কে বলো, "তুমি একজন senior engineer।" এতে সে কোন ভঙ্গিতে উত্তর দেবে, ঠিক হয়ে যায়। [STEP 3] তৃতীয় অংশ, context। ছাত্ররা দুপুরে খাবে, এটা জানলে বাবুর্চি পরিমাণ ঠিক করে। model-কেও পরিস্থিতিটা জানাতে হয়। [STEP 4] চতুর্থ অংশ, examples। "গতকালের মতো বানাও" বললে সে একটা নমুনা পায়। নমুনা থাকলে ভুল কমে। [STEP 5] পঞ্চম অংশ, constraints। "ঝাল দিয়ো না, খরচ কম রাখো।" এগুলো হলো সীমা। [STEP 6] ষষ্ঠ অংশ, format। "বাটিতে দাও।" model-কে বলো, "শুধু একটা function দাও।" ছয় অংশ মিলে একটা ভালো prompt হয়। এখন দেখি এটা কাজে কেমন চলে।

[STEP 1] এবার আসল ফল দেখি। প্রথমে ছোট prompt: "write a BD phone number validator"। এক লাইন, শুধু task। আমরা সবাই প্রতিদিন প্রায় এভাবেই লিখি। [STEP 2] [DEMO P1] [DO: P1 cast নিজে চলবে] [PAUSE 5s] দেখো, model একটা পুরো উত্তর লিখছে। সঙ্গে ব্যাখ্যা, comment আর test। আমরা কিন্তু কোনো ভাষার নাম বলিনি। [STEP 3] ফল: model Python বেছে নিয়েছে। উত্তর 30 লাইনের। output ছিল 693 token, তার ভেতরে thinking_tokens 176। বাকি 517 token আসল উত্তর। এটা model-এর দোষ না। আমরা বলিনি, তাই সে অনুমান করেছে। অথচ আমাদের লাগত শুধু একটা JavaScript function। চলো দেখি, prompt বদলালে কী বদলায়। [STEP 4] এবার structured prompt। ছয় অংশ: role, task, context, দুইটা example, constraints আর output format। প্রতিটা অংশ আলাদা লাইনে। [STEP 5] [DEMO P2] [DO: P2 cast নিজে চলবে। prompt পর্দায় এলে শেষ লাইনটা পড়ে শোনাও।] [PAUSE 5s] শেষ লাইনে লেখা: শুধু একটা JavaScript function, আর কোনো লেখা নয়। model ঠিক তাই দিয়েছে। [STEP 6] ফল: JavaScript, মাত্র 6 লাইন। output 357 token, তার ভেতরে thinking_tokens 262। বাকি 95 token আসল উত্তর। বাড়তি কথা নেই। আগেরটা 30 লাইন, এটা 6 লাইন। এই সংখ্যাগুলো এই recording থেকে নেওয়া, আমি বানাইনি। কিন্তু ছোট হলেই কি ঠিক? সেটা পরের slide-এ test করে দেখব।

Normal numbers pass. Edge numbers break the naive prompt

The naive prompt has only a task. Which part makes the naive validator accept 017-1234-5678?

  1. Role
  2. Context
  3. Examples
  4. Constraints
  5. Format
Answer D: Constraints. One line rejects 017-1234-5678.

  2. Play P3. The test runs 6 normal numbers.
  3. Both validators pass 6 of 6 normal numbers.

[STEP 1] [ASK] naive prompt-এ শুধু task আছে। role, context, examples, constraints আর format নেই। বলো, কোন অংশ না থাকায় naive validator 017-1234-5678 নম্বরটা মেনে নেবে? A, B, C, D, নাকি E? [PAUSE 10s] হাত তোলো। কেউ কেউ নিশ্চয়ই অন্য অংশ বলেছ, ভালো। উত্তর এখনই বলছি না। আগে test চালাই। [STEP 2] [DEMO P3] [DO: P3 cast নিজে চলবে] এখানে ছয়টা সাধারণ number: তিনটা valid, তিনটা invalid। [PAUSE 5s] naive code হলো Python, তাই সেটা python3 দিয়ে চলছে। [STEP 3] ফল: দুইটাই 6 এর মধ্যে 6 পাশ! সাধারণ number-এ কোনো তফাত নেই। শুধু এই test করলে আমরা কিছুই ধরতে পারতাম না। [STEP 4] [DEMO P4] [DO: P4 cast নিজে চলবে] এবার তিনটা edge number: মাঝখানে dash দেওয়া number, প্রথমে শূন্য নেই এমন number, আর শুরুতে space-ওয়ালা number। [PAUSE 5s] [STEP 5] ফল: naive দুইটা number-কে true বলেছে, dash-ওয়ালাটা আর space-ওয়ালাটা। আমাদের spec-এ তিনটাই false। structured তিনটাতেই false বলেছে। উত্তর D, constraints। prompt-এ লিখেছিলাম, "শুধু এই তিন format নাও।" এই এক লাইনই বাকিটা আটকেছে। মনে রেখো, এটা সব অংশ আলাদা করে খুলে করা পরীক্ষা না, এটা একটা উদাহরণ। আর model-এর উত্তর প্রতিবার একরকম হয় না, তাই এই recording-ই আমাদের প্রমাণ।
