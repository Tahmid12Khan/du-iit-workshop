An agent is a loop: context, plan, act, check

  1. Context: the model sees the task and all earlier results.
  2. Plan: the model picks the next action.
  3. Act: our code runs the action.
  4. Check: if the task is not done, the loop repeats.
  5. Stop: the loop ends at a final answer or at the step limit.
[STEP 1] এবার আজকের সবচেয়ে বড় idea: agent মানে একটা loop। Dhaka-র রাস্তার কথা ভাবো। তুমি Google Maps খুলে গাড়ি চালাচ্ছ। প্রথমে তুমি live map দেখো, কোথায় জ্যাম। agent-এ এটাই context। মানে task আর আগের সব ফল, যা model এখন দেখতে পায়। [STEP 2] এরপর তুমি সেরা route বেছে নাও। এটা plan। model ঠিক করে পরের action কী হবে। মনে রেখো, model শুধু একটা action বাছে, পুরো রাস্তা একবারে ঠিক করে না। [STEP 3] তারপর এক block গাড়ি চালাও। এটা act। কিন্তু মনে রেখো, agent-এ act করে আমাদের code, model না। এই কাজটা আমরা একটু আগেই tool call হিসেবে দেখেছি। [STEP 4] তারপর আবার map দেখো। পৌঁছেছি? না পৌঁছালে আবার দেখো। এটা check। task শেষ না হলে তীরটা ঘুরে আবার context-এ ফেরে। এভাবেই loop ঘোরে: দেখো, ভাবো, করো, মেলাও। পৌঁছালে শেষ, না পৌঁছালে আবার প্রথম থেকে। [STEP 5] কিন্তু Dhaka-র রাস্তায়ও তো চিরকাল ঘোরা যায় না। loop থামার দুটো উপায় আছে। হয় model final answer দেয়, নয়তো step limit-এ পৌঁছে যায়। মাঝের counter দেখো: আজকের একটা run-এ ছয় step লেগেছে, limit ছিল আট। একটু পরে আমরা সেই run-টা চোখের সামনে দেখব। খেয়াল রেখো, এই ছয়টা সংখ্যা আমাদের recording থেকে নেওয়া। [ASK] ভাবো তো, step limit না থাকলে কী হতে পারে? [PAUSE 5s] ঠিক, loop কখনো থামবে না, আর প্রতি step-এ খরচ হতে থাকবে।

The agent finishes the task in 6 steps

  1. Run the loop with a limit of 8 steps. The task: find the longest note.
  2. Play L2. Each step shows context, plan, act and check.
  3. Steps 1 to 5 are tool calls: list_dir, then 4 read_file calls.
  4. Step 6 is the final answer. The check ends the loop.
  5. Result: gradient-descent.md is the longest note. The loop used 6 of 8 steps.
[STEP 1] এবার সেই loop চালাব। task হলো: ./notes folder-এ চারটা note আছে। কোনটা সবচেয়ে বড় আর সেটা কী নিয়ে? খেয়াল করো, list_dir শুধু file-এর নাম দেয়, size দেয় না। তাই model আগে থেকে জানে না কোনটা বড়। command হলো MAX_STEPS=8 node loop.mjs। মানে limit আট step। [STEP 2] [DEMO L2] [DO: L2 cast এই step-এ নিজে চলবে] দেখো, প্রতি step-এ চারটা লাইন আসছে। context, plan, act, check। context-এর transcript প্রতি step-এ বড় হচ্ছে। plan-এ model বলছে কী করবে। act-এ আমাদের code কাজটা করছে। check বলছে, এখনো শেষ হয়নি। মনে রেখো, এই run-টা recording। আবার চালালে model হয়তো অন্য ক্রমে file পড়বে। [PAUSE 5s] [STEP 3] প্রথম পাঁচ step-এ model শুধু tool চেয়েছে। আগে list_dir, তারপর চারটা read_file: trip, schedule, gradient-descent, budget। বাঁয়ের table-এ দেখো, প্রতিটা tool কত character ফেরত দিয়েছে। ডানের Tool runs counter বলছে, পাঁচবার আমাদের code কাজ করেছে। [STEP 4] ছয় নম্বর step-এ model বুঝল তার কাছে যথেষ্ট তথ্য আছে। সে final_answer দিল। check দেখল কাজ শেষ, তাই loop থামল। মানে model নিজেই বলে দেয় কখন সে শেষ করছে, আমাদের loop শুধু দেখে action-টা final_answer কি না। উত্তর ঠিক কি না, এই code যাচাই করে না। সেই যাচাই আমাদেরই যোগ করতে হয়। [STEP 5] উত্তর: gradient-descent.md সবচেয়ে বড়, 906 character। আটের মধ্যে ছয় step, তাই দুটো step বেঁচে গেছে। সময় লেগেছে 32.6 সেকেন্ড। প্রতিটা model call-এ একটু সময় যায়, তাই step বেশি মানে অপেক্ষাও বেশি। [ASK] model সব file কেন পড়ল? [PAUSE 5s] কারণ list_dir শুধু নাম দেয়, size দেয় না। তাই পড়া ছাড়া উপায় ছিল না।

A step limit stops a loop that does not finish

  1. Set the step limit to 4. The L2 run needed 6 steps.
  2. Play L3. The model reads files one at a time.
  3. Steps 1 to 4 are tool calls. Step 4 is the last step allowed.
  4. The limit stops the loop. The program prints GUARDRAIL.
  5. Result: no answer and exit code 1. The model did not read budget.md.
[STEP 1] এবার একই task, কিন্তু limit চার। আগের run-এ ছয় step লেগেছিল, তাই চারে হবে না। command হলো MAX_STEPS=4 node loop.mjs। এটা একটা guardrail, মানে একটা দেয়াল, যেটা loop-কে চিরকাল ঘুরতে দেয় না। [STEP 2] [DEMO L3] [DO: L3 cast এই step-এ নিজে চলবে] model আগের মতোই একটা একটা করে file পড়ছে। কিন্তু এবার একটা দেয়াল আছে। দেখো, step সংখ্যা চারের দিকে এগোচ্ছে। [PAUSE 5s] [STEP 3] চার step পর্যন্ত চারটা tool চলল: list_dir, তারপর trip, schedule আর gradient-descent। চার নম্বর step-ই শেষ step। এখনো model-এর হাতে উত্তর নেই। [STEP 4] এবার loop থামল। program একটা GUARDRAIL message ছাপল। model তখনো উত্তর দেয়নি। [STEP 5] ফল: কোনো answer নেই, exit code 1। budget.md পড়া হয়নি। [ASK] উত্তর ছাড়া থামা কি ভালো? [PAUSE 5s] হ্যাঁ। loop চিরকাল ঘুরতে থাকার চেয়ে পরিষ্কার error দিয়ে থেমে যাওয়া ভালো, কারণ তাতে সবাই জানতে পারে কিছু ঠিক হয়নি। তাই বাস্তব system-এ সবসময় একটা limit রাখো।

Each step sends the full context again

  1. Step 1 sends 1583 input tokens.
  2. Each tool result adds text. Step 6 sends 2298 input tokens.
  3. The model reads the full context at every step. The 6 steps used 11,394 input tokens.
[STEP 1] এখানে একটা জিনিস খেয়াল করো। প্রথম step-এ model 1583 token পড়ল। এর বেশিরভাগই নির্দেশনা, task খুব ছোট। [STEP 2] প্রতিটা tool-এর ফল transcript-এ জমে। তাই ছয় নম্বর step-এ model পড়ল 2298 token। প্রতি step-এ model পুরো context আবার পড়ে, কারণ তার কোনো memory নেই। যেন পরীক্ষার খাতাটা প্রতিবার গোড়া থেকে আবার পড়ে শোনাতে হচ্ছে। [STEP 3] ছয় step মিলিয়ে মোট 11,394 token। loop যত লম্বা, খরচ তত বাড়ে, আর কাজও তত ধীর হয়। তাই step limit জরুরি।
