Software needs fields, not prose

  1. A person reads prose with ease.
  2. Software needs fields. Each field has a name and a type.
  3. The model reads the prose and fills the fields.
  4. Each field keeps its type. The fee is a number.
[STEP 1] একটা নোটিশ লিখলে মানুষ সেটা সহজে পড়ে বোঝে। এটা prose। এই hackathon-এর নোটিশটা দেখো: নাম, তারিখ, জায়গা, fee, সব এক prose-এ। আমাদের চোখে এটা পরিষ্কার। [STEP 2] কিন্তু software এই prose বোঝে না। সে চায় একটা application form-এর মতো ঘর: নামের ঘর, তারিখের ঘর, fee-র ঘর। প্রতিটা ঘরের একটা নাম আর একটা type আছে। event string, date string, venue string, fee number। [STEP 3] আমরা model-কে বলি, prose পড়ে ঘরগুলো ভরে দাও। রঙিন দাগগুলো দেখো: কোন লাইন থেকে কোন ঘর ভরল। [STEP 4] fee-র ঘরটা দেখো। type হলো number। এই একটা type আমাদের code-কে বাঁচায়। fee-র সঙ্গে 100 যোগ করা যাবে, কারণ সেটা সংখ্যা। [ASK] আর text হলে কী হতো? "Tk 500" যোগ 100? [PAUSE 3s]

  2. Play S1. Node reads the reply.
