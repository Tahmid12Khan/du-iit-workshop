DeckVideosWorksheet

Worksheet: Foundations of LLMs and Agentic Systems

Do these eight tasks at home, one for each topic of the session. Each task has one result to find.

Cost rule

Every command in this worksheet has --max-budget-usd 0.10. The flag stops a call that costs more than 10 US cents.

The helpers cc and tokens in demo/cc.sh already set this flag. When you call claude -p yourself, add the flag.

Tasks 2 and 4 use Claude Code in interactive mode. This mode has no budget flag. Use the model haiku to keep the cost low.

Before you start

  1. Install Claude Code and log in. Run claude --version to check.
  2. Use macOS, Linux, WSL or Git Bash. Install Node.js 20 or newer, jq and python3.
  3. Open a terminal in the repo folder.
  4. Load the helpers. cc calls the model without the Claude Code overhead. tokens counts the input tokens of a text.
cd "$(git rev-parse --show-toplevel)/workshop-1"
source demo/cc.sh

The commands work in bash and in zsh. In zsh, do not paste a line that starts with #. An interactive zsh does not accept comments, and the line fails.

Run the second command again in each new terminal window. Each task also has a demo script in demo/. Run it to see the presenter version.

Tokens

Demo scripts: demo/T1.sh to demo/T5.sh

Goal. Count the tokens of four texts. Find which text costs the most.

  1. Look at the raw usage fields for one word.
  2. Count the baseline. The baseline is the cost of a single dot.
  3. Count each text. The net count is the total count minus the baseline.
cc "Hello" --max-budget-usd 0.10 | jq '.usage | {input_tokens, cache_creation_input_tokens, cache_read_input_tokens}'
tokens "."
tokens "Hello"
tokens '{"greeting":"Hello"}'
tokens 'const sum = (a, b) => a + b;'
tokens 'Software engineers build reliable systems by testing early and often.'

Bonus. Count one line of Python and one line of JavaScript that do the same job. Compare the two counts.

What to notice

  • The usage has three input fields. The helper adds them.
  • The same word costs more tokens inside JSON.
  • Code costs a different number of tokens per word than English text.

Effort levels

Demo scripts: demo/E1.sh to demo/E3.sh

Goal. Ask one puzzle three times at low effort and three times at max effort. Compare the answers, the tokens and the time.

The correct answer is 27.

PUZZLE="How many integers from 1 to 5000 inclusive are divisible by 13 and have digits that add up to exactly 14? Reply with only the number."

for i in 1 2 3; do
  cc "$PUZZLE" --effort low --max-budget-usd 0.10 \
    | jq -r '[.result, .usage.output_tokens, (.duration_ms/1000)] | @tsv'
done
for i in 1 2 3; do
  cc "$PUZZLE" --effort max --max-budget-usd 0.10 \
    | jq -r '[.result, .usage.output_tokens, (.duration_ms/1000)] | @tsv'
done

Each line shows: answer, output tokens, seconds.

Bonus. Use the harder puzzle in demo/E3.sh (the correct answer is 805).

What to notice

  • Max effort writes more output tokens. Most of them are thinking.
  • More tokens usually means more seconds and more cost.
  • The answers at low effort can differ from run to run.

Hallucination

Demo files: demo/H1.claude to demo/H4.claude

Goal. Check two model answers against the npm registry. Find which answer is wrong and why.

In the terminal, start Claude Code with no tools. The model can then use only its training data:

claude --model haiku --tools "" --strict-mcp-config --setting-sources "" --no-chrome

In Claude Code, type each line and wait for the answer. A line that starts with ! runs a shell command. The model sees its output.

Reply with ONLY the latest version number of the npm package express. No other words.
!npm view express version
What config options does the npm package fastjson-validator-kit support? If you are not sure, say I don't know.
!npm view fastjson-validator-kit version 2>&1 | head -3
/exit

Bonus. Ask the second question again without the sentence "If you are not sure, say I don't know." Compare the two answers.

What to notice

  • The model knows only the data from its training time. Its version number can be old.
  • The model can give an old answer with no sign of doubt.
  • The registry is the source of truth. The model is not.
  • A model can say "I don't know" for a package that does not exist. Always check with npm view.

Structured output

Demo scripts: demo/S1.sh to demo/S3.sh

Goal. Get JSON that code can use with no cleanup. Compare a prompt only with a prompt and a schema.

cat demo/structured/notice.txt
cat demo/structured/schema.json

cc "Extract event, date, venue and fee as JSON from: $(cat demo/structured/notice.txt)" \
  --max-budget-usd 0.10 | jq -r .result | node demo/structured/plain.mjs

cc "Extract the event, date, venue and fee from: $(cat demo/structured/notice.txt)" \
  --json-schema "$(cat demo/structured/schema.json)" \
  --max-budget-usd 0.10 | node demo/structured/parse.mjs

Run each command three times. The model can answer in a different way each time.

Bonus. Change fee to a string in the schema. Run the second command again.

What to notice

  • Without a schema, the answer can have extra text or a code fence. JSON.parse then fails.
  • With a schema, the answer has the fields and types that the schema names.
  • The type of fee follows the schema. A number lets you add to it.

Write down. How many of three runs parsed with no schema? What is typeof fee with the schema?

Agent loop

Demo scripts: demo/L2.sh and demo/L3.sh

Goal. Put your tool call in a loop. The loop answers: which file in ./notes is longest, and what is it about?

  1. Open my-loop.mjs from task 7. Do TODO 2.
  2. In each step, print the four parts: context, plan, act, check.
  3. Stop when the model returns final_answer. Stop at MAX_STEPS if it does not.
  4. Run the loop with a step limit of 8. Run it again with a step limit of 4.
cd "$(git rev-parse --show-toplevel)/workshop-1/demo"
MAX_STEPS=8 node my-loop.mjs
MAX_STEPS=4 node my-loop.mjs

Compare your output with bash L2.sh and bash L3.sh.

Bonus. Add a fifth note to demo/notes. Run the loop again.

What to notice

  • The transcript grows in each step. The model sees more tokens in each call.
  • With a step limit of 4, the loop stops with no answer. The step limit is a guardrail.
  • The model chooses the order of the steps. You do not.

Write down. At which step did the model answer? What did it read before that?
